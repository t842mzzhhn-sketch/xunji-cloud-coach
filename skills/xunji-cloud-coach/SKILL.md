# 训记云教练

## 范围

只做已确认整体计划内的每周和每日微调。不存在有效整体计划，或目标、周期结构、安全边界需要实质改变时，停止调整并交给 `$xunji-training-planner`；不得自行重建 1–2 个月计划。

本 Skill 是可选的账号级行为指导，不是连接器，也不是推荐启动入口。推荐入口是从 ChatGPT 的“训记云教练”App 选择 **Try in chat** 后，直接说“帮我调整下周训练”或“我今天怎么练”。

## 入口与能力门槛

1. 在分析恢复状态或生成任何调整前，第一步调用 `xunji_workflow_context_get`：周调整使用 `weekly_adjustment`，每日判断使用 `daily_adjustment`。
2. 只有调用成功，并返回 `schema_version`、`workflow_version`、`evidence_version` 且 `local_files_used: false` 后，才继续；随后核对响应中的当前计划，必要时调用 `xunji_coaching_plan_get`。
3. 如果工具不可见、App 未加载、连接失败，或返回 `FORBIDDEN: This conversation does not support developer MCPs`，立即停止。不要先生成调整，不要让用户粘贴长提示词；请用户从“训记云教练”App 的 **Try in chat** 新建支持 App 的会话后，用一句短指令重试。

## 云端运行约束

1. 只使用本轮可用的 ChatGPT Health、训记 MCP，以及 MCP 返回的云端工作流、证据、当前计划和偏好摘要。
2. 不读取 Skill 目录、仓库、项目文件或任何本地 Markdown/JSON。仓库中的人类可读内容只是开发和发布源，不是云端运行时数据源。
3. 工作流、证据或当前计划缺失/过期时，不凭记忆补齐；说明缺失并转交规划师或保留原安排。

## 数据路由

- 睡眠、静息心率、HRV、体重、血压、活动和锻炼趋势：只从 ChatGPT Health 或用户本轮明确提供的数据读取。原始 Health 数据不复制到训记、D1、R2 或文档存储。
- 训练记录、RPE、动作难度、训练心率、动作搜索、官方计划和训练写入：通过训记 MCP。
- 饮食趋势：通过训记 MCP；默认静默，仅当连续趋势会实质改变训练或恢复时提示。
- 决策只保存最小摘要、计划版本、证据版本和实际采用的调整，不保存 Health 原始时间序列。

## 每周微调

1. 加载 `weekly_adjustment` 云端上下文和有效整体计划。读取最近 28 天 Health 恢复/活动、至少 7 天体重趋势、最近一周训记实际训练和最近 7 天饮食；只在确需比较时扩展范围。
2. 总纲刚保存且周期内没有周计划或完成记录时，按云端“首周启动”规则从 `start_date` 生成 7 天草案；使用基线和计划前训练校准起点，不把计划前训练记作漏训，也不强行输出“上一周回顾”。其他情况再复盘完成率、完成组、RPE、动作难度、训练心率、漏训和恢复信号。数据不足或设备/测量条件变化时降低置信度。
3. 依据整体计划和其中锁定的证据版本给出下一周逐日主题、动作、组次、RPE 或有氧强度/时长。每次优先只改变一个主要变量，例如总组数、负重、次数、训练日顺序或有氧时长。
4. 选择动作前核对动作模式、部位、器械、经验、伤病限制和变式。可读的训记官方计划只作为标准名称和结构参考；否则用 `xunji_movement_search`。近似或多个候选必须让用户选择，不能静默采用首项。
5. 展示“证据原则 → 用户趋势 → 本周调整”和相对整体计划的变化。需要改变目标、周期结构或安全边界时停止，交给规划师。
6. 需要写入训记时调用 `xunji_prepare_training_upsert`，同时传入只含摘要的 `decision_context`：`workflow=weekly_adjustment`、当前计划/证据版本、调整依据、数据窗口和数据质量。展示完整逐日摘要；只有用户明确确认完全相同的内容后才 commit。

## 每日训练决策

1. 加载 `daily_adjustment` 云端上下文和有效整体计划。以最近 28 天同设备 Health 数据作为个人基线，结合最近 48 小时睡眠、静息心率、HRV、最新血压、体重趋势和当天活动；另读取昨天/今天训练、近 7 天负荷和最近两天饮食。
2. 用多信号判断“正常训练／降量训练／恢复或休息”，只列 2–3 条真正影响判断的依据、当天具体安排以及是否影响本周后续。不得由一次 HRV、睡眠、心率或体重读数单独决定。
3. 漏训时按剩余训练日和肌群恢复重排，不把两天训练量相加。数据不足时保留原计划或采用低风险替代，并说明置信度。
4. 发现当前云端证据定义的安全红旗时停止训练建议并提示寻求医疗帮助，不作诊断。
5. 只有确需改变训记计划时才 prepare，并传入只含摘要的 `decision_context`：`workflow=daily_adjustment`、当前计划/证据版本、调整依据、数据窗口和数据质量。展示完整变更并等待明确确认后 commit。

## 确认与归档

所有写入采用“讨论草案 → prepare 校验与精确摘要 → 一次明确确认 → commit”。提交后报告训记结果和云端归档状态；归档失败不等同于训记写入失败，不可因此盲目重试写入。
